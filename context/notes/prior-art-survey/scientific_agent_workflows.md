# Scientific workflow engines and LLM-agent systems for computational chemistry/materials — prior art for "agent-in-every-node, durable, provenance-tracked DAG CLI"

Date of research: 2026-10-02. Verification legend: items marked **[verified this session]** were checked against the cited page during this research; items marked **[prior knowledge, not re-verified]** come from background knowledge with canonical URLs and should be spot-checked before publication. Some fetched summaries were produced by a summarizing fetch tool; odd details (e.g., model names) are flagged.

## Q1. Which systems are closest, and does any already do "agent in every node + durable HPC execution + provenance"?

### Takeaway
No system found does all three together. The field splits into (a) mature, durable, provenance-rich workflow engines (AiiDA, jobflow/jobflow-remote, FireWorks, dflow, Parsl, signac) whose nodes are fixed functions and which only recently gained thin LLM/MCP front-ends; and (b) LLM-agent systems for DFT/MD (DREAMS, VASPilot, AutoDFT, El Agente, ChemGraph, OpenClaw+skills, CatGo) where an LLM plans and calls fixed tools, often submits Slurm jobs, but the "workflow" is an implicit agent loop/task list, rarely a durable, user-approved, resumable DAG. The closest single points: **DREAMS** (LLM agent per role + Slurm + automatic DAG provenance graph with immutable artifact IDs), **OpenClaw "Agent Taskboard Manifest" + DPDispatcher** (general coding-style agent + an explicit staged/dependency manifest + Slurm/PBS/LSF), **CatGo** (visual DAG editor + HPC monitoring + MCP server for Claude Code), **Diamond Agent** (event-driven continuation that resumes the agent only when long batch jobs produce results), and **Academy** (durable agents on HPC via Parsl/Globus Compute, but agents are generic, not per-node LLM harnesses).

### Cited Findings
- **DREAMS** (Wang, Huang, Zhao, Xu, Zhu, Janssen, Viswanathan; arXiv:2507.14267, v2 dated Aug 2026 per fetched page): hierarchical multi-agent DFT system — planning supervisor + specialized worker agents (DFT, HPC, convergence diagnosis) + safety-guard verification layer; each agent is an LLM with role-specific prompts. Shared "canvas" with append-only notes, artifact registry with immutable identifiers, immutable verified reports; "directed acyclic provenance graph assembles automatically during execution"; HPC agent submits via pysqa to SLURM and monitors jobs; convergence agent diagnoses failures from input/output/error files; no human plan approval (supervisor assigns autonomously). Fetched summary lists Claude Sonnet 4.5 for agents and "Claude Opus 4.8" for judges — model naming is unverified/suspicious. Code repo not identified. **[verified this session, details via summarizer]** — [arXiv 2507.14267](https://arxiv.org/html/2507.14267)
- **VASPilot** (Liu, Zhu, Ye, Fang, Weng, Wu; arXiv:2508.07035, Aug 2025): CrewAI multi-agent (manager, crystal-structure, VASP, result-validation agents) + MCP server for tools; Slurm submission, monitoring, automatic restarts with adjusted parameters; Flask web UI; task records; summarizer claims human-in-the-loop approval for critical decisions (not independently confirmed). GitHub: JiaxuanLiu-Arsko/VASPilot; hosted at IOP CAS MaterialsGalaxy. **[verified this session]** — [arXiv 2508.07035](https://arxiv.org/pdf/2508.07035); [GitHub](https://github.com/JiaxuanLiu-Arsko/VASPilot)
- **Masgent** (Digital Discovery 2026, DOI 10.1039/D6DD00043F; arXiv:2512.23010): natural-language materials simulation agent unifying structure manipulation, VASP input generation, DFT workflow construction/analysis, MLP simulations; for HPC it *generates* SLURM-ready job scripts (nodes, tasks, walltime, partition, modules) rather than running a durable scheduler. **[verified via search snippet]** — [Digital Discovery](https://pubs.rsc.org/en/content/articlehtml/2026/dd/d6dd00043f); [arXiv](https://arxiv.org/pdf/2512.23010v1)
- **AutoDFT** (Penghui Yang et al.; arXiv:2605.26179, May/Jun 2026): three LLM components — strategic planner (skeletal step objectives), step planner (numerical parameters generated dynamically), and monitor-recover-reflect cycle; claims to "embed LLM reasoning into every stage" vs. prior upfront plans; inserts intermediate steps as results reshape the problem (i.e., dynamic plan growth); 94.1% task success on VASPBench (34 tasks) with GPT-5.2. HPC/provenance/code not stated in abstract. **[verified this session]** — [arXiv 2605.26179](https://arxiv.org/abs/2605.26179)
- **VASP Agent** (arXiv:2512.19458) and **TritonDFT** (arXiv:2603.03372) are additional 2025–26 multi-agent DFT frameworks surfaced by search; not examined in detail. — [VASP Agent](https://arxiv.org/html/2512.19458); [TritonDFT](https://arxiv.org/pdf/2603.03372)
- **OpenClaw + domain skills for computational chemistry** (Ding, Huang, ..., Gu, Jinzhe Zeng; arXiv:2603.25522 v2, May 2026): a *general-purpose* agent (OpenClaw) + reusable skills; an "Agent Taskboard Manifest" skill converts task descriptions into executable specs with stages, dependencies and validation criteria; DPDispatcher skill grounds HPC submission/monitoring/retrieval across Slurm, PBS, LSF; skills loaded on demand; bounded recovery, halts or "requests human guidance"; no explicit pre-execution approval gate described. This is the closest "general coding-agent harness + explicit dependency manifest + real HPC" prior art found. **[verified this session]** — [arXiv 2603.25522](https://arxiv.org/html/2603.25522)
- **CatGo** (Hello-QM/UCSD; Digital Discovery 2026 vol 5 p.3825 "CatGo: Bridging CLI coding agents with interactive structure and workflow management for computational chemistry"; ChemRxiv 10.26434/chemrxiv.15002984): AGPL-3.0; `pip install catgo`; browser app with 3D structure editor, *visual DAG workflow editor*, HPC job submission/monitoring, NL assistant; `catgo setup` registers a CatGo MCP server for Claude Code; supports VASP, CP2K, ORCA, MLP, LAMMPS; search snippet says CLI coding agents (Claude Code, Codex CLI) "construct, modify, validate, and execute workflows through MCP-enabled interfaces." DAG nodes appear to be fixed calculation steps (single_point/geo_opt/cell_opt/MD), with the coding agent as outer editor — not agent-per-node. Journal page returned 403; details from PyPI/search snippets. **[partially verified]** — [Digital Discovery](https://pubs.rsc.org/dd/article/5/9/3825/1288793/CatGo-Bridging-CLI-coding-agents-with-interactive); [PyPI](https://pypi.org/project/catgo/); [GitHub](https://github.com/Hello-QM/catgo-LRG)
- **Diamond Agent** (Haotian Xie et al.; arXiv:2609.06181, Sep 2026): single centralized agent orchestrating multiple supercomputers via "typed skills"; Globus Transfer for data; site-specific execution translation; "event-driven continuation mechanism decouples agent actions from long-running batch jobs"; "persistent services monitor remote execution and resume the agent only when a result or decision-relevant event is available"; overhead reduced 42 s → 4 s median across 83 jobs on four supercomputers. Directly relevant to the durable-HPC + agent-wakeup design; no DAG/provenance claims in abstract. **[verified this session]** — [arXiv 2609.06181](https://arxiv.org/abs/2609.06181)
- **Academy** (Kamatar, Sakarvadia, Pauloski, Babnigg, Babuji, K. Chard, R. Chard, Foster; arXiv:2505.05428 v3, Jan 2026): Python middleware for stateful agents across federated infrastructure; agents have `@action` (remote-callable) and `@loop` (autonomous control) methods, exchanges (mailboxes, message persistence), executors/launchers for threads, processes, Parsl, Globus Compute; tested on Aurora/Polaris; State API with app-defined checkpointing; agents are generic (LLM optional); limited explicit provenance. Applications: MOFA (MOF discovery), spectroscopy, 1500+ agent decentralized learning. Org: github.com/academy-agents. **[verified this session]** — [arXiv 2505.05428](https://arxiv.org/html/2505.05428v3); [Globus Labs](https://labs.globus.org/projects/academy.html)
- **Chiltepin** (NOAA-related) is a library exploring federated agentic workflows with Parsl, Globus Compute and Academy agents on HPC. — [Chiltepin docs](https://chiltepin.readthedocs.io/en/latest/)
- **ChemGraph** (Argonne CSD/ALCF; arXiv:2506.06363; PMC article): LangGraph-based ReAct agent(s) over ASE + ML potentials/quantum codes (SMILES→structure→geometry optimization→vibrations→thermochemistry); multi-agent decomposition lets GPT-4o reach perfect accuracy on 13 benchmark tasks; Parsl used for HPC orchestration; ChemGraph-XANES extension (arXiv 2604.16205) built on ASE, FDMNES, Parsl, LangGraph. Agents call fixed tools; graph is LangGraph control graph, not a durable scientific DAG. **[verified via search snippets]** — [arXiv 2506.06363](https://arxiv.org/pdf/2506.06363); [PMC](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC12824235/); [ChemGraph-XANES](https://www.alphaxiv.org/abs/2604.16205.md)
- **El Agente Q** (Zou et al., Aspuru-Guzik group with NVIDIA/Vector/Acceleration Consortium; arXiv:2505.02484): LLM multi-agent system that dynamically generates and executes quantum-chemistry workflows from NL; hierarchical memory; "autonomous file handling and submission"; in-situ debugging; >87% task success on six course exercises; "detailed action trace logs" for transparency. — [arXiv 2505.02484](https://arxiv.org/abs/2505.02484v2). Successor **El Agente Quntur** (Pérez-Sánchez et al.; arXiv:2602.04850, v3 Sep 2026): hierarchical multi-agent "research collaborator" covering the full range of ORCA 6.0 calculations, reasoning-driven rather than hard-coded policies; HPC details not in abstract. **[verified this session]** — [arXiv 2602.04850](https://arxiv.org/abs/2602.04850v1)
- **MDCrow** (arXiv:2502.09565, ICLR 2025 workshop): LangChain ReAct agent with 40+ expert tools (OpenMM, MDTraj, PackMol, PDB, literature); gpt-4o best. Single-agent tool-calling, not a DAG engine. **[verified via search snippet]** — [arXiv 2502.09565](https://arxiv.org/pdf/2502.09565)
- **LARA-HPC** (Dawson, Beal, Curé, Fisicaro, Rolland, Genovese; arXiv:2604.22571, Apr 2026): "validation-driven agentic supercomputer workflows for atomistic modeling" — a controlled execution layer mediating all HPC interactions, simulation-native dry-run validation, multi-phase agentic pipeline with RAG + iterative refinement (BigDFT group). DAG/scheduler details not in abstract. **[verified this session, abstract only]** — [arXiv 2604.22571](https://arxiv.org/abs/2604.22571)
- **MAESTRO** (arXiv:2608.20434, Aug 2026): LLM agent executing the entire MOF screening pipeline end-to-end (literature → structures → computation-ready database). Not examined in detail. — [arXiv 2608.20434](https://arxiv.org/abs/2608.20434)
- **Anthropic "Long-running Claude for scientific computing"** (Mar 23, 2026): recommends Claude Code on HPC/SLURM in tmux with CLAUDE.md (plan/objectives), CHANGELOG.md as "portable long-term memory", a test oracle, git commits per work unit, "Ralph loop" re-prompting; no DAGs or formal provenance. This is the de-facto "single long agent + progress file" baseline the idea improves upon. **[verified this session]** — [Anthropic](https://www.anthropic.com/research/long-running-Claude)
- Search also surfaced "Claude Science" (an Anthropic AI workbench reportedly launched Jun 2026 with HPC/Slurm job orchestration over SSH and Modal) only via a third-party blog — **unverified**. — [paperguide blog](https://paperguide.ai/blog/how-to-use-claude-science/)
- **LQCDMaster** (arXiv:2607.15001) compared against Claude Code as a general coding-agent baseline; reports general coding agents without domain skills failed on certain lattice-QCD tasks. **[search snippet only]** — [arXiv 2607.15001](https://arxiv.org/pdf/2607.15001)

### Inferences
- The specific combination "every DAG node is a headless coding-agent session (claude -p / codex exec), DAG approved as a contract, durable across sessions, per-node rerun, append-only event log including agent decisions" is not occupied by any found system. DREAMS covers provenance + Slurm + LLM-per-role but is a fixed hierarchical agent team, not a user-editable DAG; OpenClaw+Taskboard Manifest covers a general agent + dependency manifest + HPC but appears to be a single agent following a manifest; CatGo covers DAG + HPC + Claude Code MCP but its nodes are fixed calc steps.
- Diamond Agent's "event-driven continuation" and Academy's persistent agents are the most relevant precedents for the durability/wakeup layer; the idea could cite them as evidence that decoupling agent turns from multi-hour batch jobs is an accepted pattern.
- Most DFT agents (VASPilot, Masgent, MDCrow, ChemGraph, El Agente) use agents as planners/tool-callers over fixed tools; AutoDFT is the clearest argument for LLM reasoning "at every stage" in DFT, supporting the agent-per-node thesis empirically.

### Gaps
- DREAMS code location and whether its provenance graph supports replay/rerun of nodes — not found.
- OpenClaw paper: whether the Taskboard Manifest is persisted, resumable, or human-approved — not described in fetched content.
- CatGo full paper inaccessible (403); whether its DAG nodes can be agent-executed or edited during a run is unconfirmed.
- LARA, MAESTRO, VASP Agent, TritonDFT details beyond abstracts not checked.

## Q2. Classic scientific workflow engines: DAG, provenance, durability, dynamic graphs, LLM/agent integration

### Takeaway
These engines already solve durability, HPC scheduling, resume and provenance; jobflow/FireWorks/AiiDA support runtime graph growth. Their LLM integrations (2025–26) are thin: chat/MCP front-ends that query provenance and submit predefined WorkChains with approval gating — none makes an LLM agent the executor of each node.

### Cited Findings
- **jobflow dynamic flows** — `Response` fields: `output`, `replace` (substitute current job with a new flow), `addition` (append jobs), `detour` (switch to new jobs), `stored_data`, `stop_children`, `stop_jobflow`; number of jobs not predetermined (e.g., bulk → carve slabs → one job per slab); managers: `run_locally`, FireWorks, jobflow-remote. **[verified this session]** — [jobflow docs](https://materialsproject.github.io/jobflow/tutorials/5-dynamic-flows.html)
- **aiida-agents** (official aiidateam repo, GSoC 2026; fork GeigerJ2/aiida-agents): NL interface to an AiiDA profile with analysis/exploration/execution agents calling typed Python tools; explores provenance, diagnoses failures from WorkChain exit codes, detects stalled daemon, sets up and submits calculations (single, sequence, bulk); "nothing is written without your say-so" — every DB-modifying tool is approval-gated, CLI shows resolved inputs before confirming; `mcp` command serves read-only tools over MCP; supports OpenAI, Anthropic, OpenRouter, Ollama; MIT; alpha, no release; ~5 stars, ~93 commits. **[verified this session]** — [aiidateam/aiida-agents](https://github.com/aiidateam/aiida-agents); [GeigerJ2 fork](https://github.com/GeigerJ2/aiida-agents)
- **aiida-mcp** (khsrali): MCP server for phonon band structure calculations with AiiDA + aiida-vibroscopy; prerequisite checks (QE, Phonopy), script generation, execution management, status tracking, for Claude and other assistants. **[verified via search snippet]** — [GitHub](https://github.com/khsrali/aiida-mcp)
- **AiiDA core** **[prior knowledge, not re-verified]**: every calculation/workflow recorded as nodes in a provenance DAG (data/calc/workflow nodes, links) in PostgreSQL + repository; daemon runs processes persistently; WorkChains checkpoint between steps (plumpy) and survive daemon restarts; scheduler plugins for Slurm/PBS/SGE/LSF via transport (SSH); dynamic behaviour via WorkChain outlines (`while_`, `if_`) and submitting subprocesses at runtime; caching by hash for reuse. — [aiida.net](https://www.aiida.net); [docs](https://aiida.readthedocs.io)
- **FireWorks** **[prior knowledge]**: MongoDB LaunchPad; Fireworks in a Workflow DAG; `FWAction` supports `additions`, `detours`, `defuse_children`, `update_spec` (runtime graph growth); rerun/defuse/pause per Firework; queue launchers for Slurm/PBS. — [FireWorks docs](https://materialsproject.github.io/fireworks/)
- **jobflow-remote** **[prior knowledge]**: Matgenix daemon-based manager running jobflow Flows on remote HPC via SSH with MongoDB state, per-job retry/rerun, CLI (`jf`). — [GitHub](https://github.com/Matgenix/jobflow-remote)
- **atomate2** **[prior knowledge]**: materials workflows (VASP, CP2K, ABINIT, FHI-aims, forcefields) built on jobflow `Maker`s; uses Response replace/detour for e.g. error-dependent or structure-dependent branching. — [atomate2](https://github.com/materialsproject/atomate2)
- **dflow** (DeepModeling) **[prior knowledge]**: Python SDK compiling OPs/Steps/DAGs to Argo Workflows on Kubernetes; supports HPC via DPDispatcher/Slurm executors, step reuse ("reuse_step") for restart, dynamic loops/slices; underpins DP-GEN2, etc. — [GitHub](https://github.com/deepmodeling/dflow)
- **Parsl** **[prior knowledge]**: Python parallel scripting; implicit dynamic DAG built from futures at runtime; providers for Slurm/PBS/etc.; app memoization + checkpointing for resume. **Globus Compute**: FaaS endpoints on HPC. — [parsl-project.org](https://parsl-project.org); [Globus Compute](https://www.globus.org/compute)
- **pyiron**, **QuAcc**, **signac** **[prior knowledge]**: pyiron — IDE-like integrated environment with job database, HPC submission via pysqa (same queue adapter DREAMS uses), newer pyiron_workflow graph-based nodes; QuAcc — recipes portable across workflow engines (Parsl, Prefect, Dask, Covalent, jobflow, Redun); signac/signac-flow — file-based data space with FlowProject operations gated by pre/post conditions, scheduler submission (condition-driven, implicitly dynamic). — [pyiron](https://pyiron.org); [QuAcc](https://github.com/Quantum-Accelerators/quacc); [signac](https://signac.io)
- **Bohrium + SciMaster** (Linfeng Zhang + 49 co-authors, DP Technology/SJTU; arXiv:2512.20469, Dec 2025): Bohrium as "a managed, traceable hub for AI4S assets" turning data/software/compute/labs into agent-ready capabilities; SciMaster orchestrates them into long-horizon workflows; emphasizes stable interfaces and "recorded execution traces"; 11 representative master agents; "multi-million scale" execution signals. SciMaster lets users pause during planning and edit chain-of-thought/parameters; uses Uni-Lab's MCP service for instruments. DP also ships `bohr-agent-sdk` and "build-your-agent". **[verified this session; press-release items lower confidence]** — [arXiv 2512.20469](https://arxiv.org/abs/2512.20469); [IPS press](https://ipsnews.net/business/2025/08/19/scimaster-leads-the-scientific-agent-revolution-in-the-ai-scientist-era/); [build-your-agent](https://github.com/deepmodeling/build-your-agent); [bohr-agent-sdk](https://pypistats.org/packages/bohr-agent-sdk)

### Inferences
- jobflow `Response(replace/addition/detour)` and FireWorks `FWAction` are direct precedents for "dynamic DAG growth during execution" — an agent-per-node design can map an agent's decision to emit these same primitives, and could even use jobflow-remote/AiiDA as the durable substrate rather than reimplement it.
- aiida-agents' approval gating ("show resolved inputs, then confirm") is the closest existing UX to plan-as-contract, but at single-submission granularity, not whole-DAG approval.
- AiiDA's provenance graph records data/calc lineage but not LLM rationale; recording agent decisions as first-class provenance is a differentiator.

### Gaps
- Exact 2026 releases/stars for AiiDA, jobflow, FireWorks, dflow, Parsl, pyiron, QuAcc, signac not checked this session.
- No verified evidence of an official MCP server for jobflow/atomate2, FireWorks, dflow, or pyiron (not searched in depth).

## Q3. Broader science-agent systems (chemistry, bio, "AI scientist")

### Takeaway
General AI-scientist systems run long agent trajectories with shared memory/world models and logs, but are not DAG engines with per-node durability on HPC; chemistry lab agents are planner-over-tools.

### Cited Findings
- **Kosmos** (Edison Scientific; arXiv:2511.02824): structured world model shared between a data-analysis agent and a literature-search agent; up to 12 h runs, ~200 agent rollouts, ~42,000 lines of code and ~1,500 papers per run; 79.4% of claims accurate; deployed at biopharma (e.g., Incyte partnership). Many parallel agent trajectories coordinated through a world model rather than an explicit DAG. **[verified via search snippets]** — [arXiv 2511.02824](https://arxiv.org/html/2511.02824v2); [Edison](https://edisonscientific.com/articles/announcing-kosmos)
- **Hierarchical Server Architecture for Agentic Science** (Sochat, Milroy, LLNL; arXiv:2608.05332, Aug–Sep 2026): "secretary agents" for concurrent asynchronous negotiation/selection/dispatch of requests across cloud/edge/HPC, 51 providers, 87.71% negotiation accuracy; DOE Genesis Mission context; no DAG/provenance claims. **[verified this session]** — [arXiv 2608.05332](https://arxiv.org/abs/2608.05332)
- **[prior knowledge, not re-verified]** planner-over-tools chemistry agents: ChemCrow (Bran et al., Nat. Mach. Intell. 2024; LangChain + 18 tools) — [arXiv 2304.05376](https://arxiv.org/abs/2304.05376); Coscientist (Boiko et al., Nature 2023; planner + web/doc search + code execution + lab automation) — [Nature](https://www.nature.com/articles/s41586-023-06792-0); ORGANA (lab robotics + chemist interaction) — [arXiv 2401.06949](https://arxiv.org/abs/2401.06949); LLaMP (RAG over Materials Project + simulations) — [arXiv 2401.17244](https://arxiv.org/abs/2401.17244); MatPilot — [arXiv 2411.08063](https://arxiv.org/abs/2411.08063); AtomAgents (multi-agent alloy design with LAMMPS) — [arXiv 2407.10022](https://arxiv.org/abs/2407.10022); CACTUS (cheminformatics tool agent) — [arXiv 2405.00972](https://arxiv.org/abs/2405.00972).
- **[prior knowledge, not re-verified]** AI-scientist systems: Sakana AI Scientist v2 (agentic tree search over experiments) — [arXiv 2504.08066](https://arxiv.org/abs/2504.08066); Agent Laboratory — [arXiv 2501.04227](https://arxiv.org/abs/2501.04227); SciAgents (knowledge-graph multi-agent) — [arXiv 2409.05556](https://arxiv.org/abs/2409.05556); Google AI co-scientist (generate/reflect/rank/evolve agents with tournament) — [arXiv 2502.18864](https://arxiv.org/abs/2502.18864); FutureHouse Robin — [arXiv 2505.13400](https://arxiv.org/abs/2505.13400); Biomni (Stanford biomedical agent) — [bioRxiv](https://www.biorxiv.org/content/10.1101/2025.05.30.656746v1).

### Inferences
- AI Scientist v2's tree search and co-scientist's tournament are dynamic agent-generated graphs, but ephemeral (in-process) and not tied to durable HPC jobs or per-node rerun.
- None of these record agent decisions as a replayable event log tied to HPC job lifecycle in a user-approved plan.

### Gaps
- Aitomia, AutoChemSchematic, Denario, Uni-Lab-OS specifics not verified this session (Denario: likely arXiv 2510.26887 — unverified).
- ORGANA/Coscientist/Robin interfaces and current maintenance status not re-checked.
